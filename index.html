    How the gate works

    Flow

    1. The payer opens a session policy with a per payment cap, a cumulative cap, an expiry, tier delays and an optional operator agent plus a guardian.
    2. Off chain, the route is scored 0 to 100. The attestation hash and the commitment hash are computed locally.
    3. createEscrow verifies the commitment on chain, so the stored score is provably the attested one, then pulls tUSD8 from the payer.
    4. The tier picks the path. Low releases now, Medium waits for the session delay, High also needs the guardian signature, Critical never releases.
    5. The payer can revoke any funded escrow at any moment. A paused or revoked session freezes pending releases; funds stay reclaimable.

    Controls

    • Scoped session keys bound agent spend to caps and expiry.
    • Every state change emits an audit event for explorer verification.
    • Checks-effects-interactions ordering, a reentrancy lock and exact balance deltas guard the token flows.
    • The commitment binds chain id, contract, session, payer, recipient, amount, score, attestation and deadline.

    Honest scope

    • Testnet only. tUSD8 has no monetary value and no tokens are issued or promised.
    • The score is a routing signal from a documented educational model. It is not a certified cryptanalysis.
    • The contract performs no post quantum signatures. QDay is EVM compatible today with a post quantum migration path.
    • Until a deployment exists, every on-chain read is opt in and every write stays inside the simulator.
